# Совместный плейлист для СберЗвук × ВШЭ

Backend-основа для общего плейлиста студенческой группы или факультета. Участники
вступают в комнату по коду, предлагают композиции, голосуют и совместно определяют
порядок воспроизведения.

## Стек

- FastAPI
- PostgreSQL 16
- SQLAlchemy 2.0
- Alembic
- интерфейс Volna на HTML/CSS/JavaScript + Vite
- Docker Compose

## Быстрый запуск через Docker

```powershell
docker compose up --build
```

После запуска:

- API: `http://localhost:8000`
- Swagger: `http://localhost:8000/docs`
- состояние API и БД: `http://localhost:8000/api/health`
- PostgreSQL: `localhost:5432`

В отдельном терминале запустите интерфейс:

```powershell
npm install --prefix frontend
npm run dev
```

Откройте `http://localhost:5173`. Vite проксирует запросы `/api` в backend на
порту `8000`, поэтому гостевая сессия и воспроизведение загруженных файлов
работают в одном origin.

При первом запуске backend дождётся готовности PostgreSQL и применит миграции
Alembic. Данные PostgreSQL сохраняются в volume `postgres_data`.

Остановить контейнеры без удаления данных:

```powershell
docker compose down
```

Команда `docker compose down -v` также удаляет локальную базу. Используйте её
только для намеренного полного сброса данных разработки.

## Запуск backend без Docker

Нужны Python 3.11+ и работающий PostgreSQL.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt
Copy-Item backend\.env.example backend\.env
cd backend
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

При другой конфигурации PostgreSQL измените `DATABASE_URL` в `backend/.env`.

Загружаемые MP3, WAV, OGG, M4A, AAC, WebM и FLAC ограничены размером 15 МБ.
Backend проверяет сигнатуру содержимого, а аудио выдаётся с поддержкой Range-
запросов, необходимых браузерному плееру.

## Схема данных

Основные таблицы:

| Таблица | Назначение |
| --- | --- |
| `users` | Анонимные или именованные участники |
| `rooms` | Сообщества с уникальным кодом приглашения |
| `room_members` | Членство и роли owner/moderator/member |
| `tracks` | Метаданные библиотечных и загруженных аудиофайлов |
| `playlist_rounds` | Недельные и ручные раунды плейлиста |
| `queue_items` | Состояние трека внутри конкретного раунда |
| `votes` | Текущее значение голоса участника |
| `vote_events` | Неизменяемая история всех изменений голосов |
| `playback_history` | Запуски и завершения воспроизведения |
| `moderation_logs` | Журнал действий модераторов |
| `favorites` | Личное избранное пользователей |

Трек намеренно отделён от элемента очереди. Поэтому повторная недельная ротация
создаёт новые `queue_items`, не уничтожая голоса и историю предыдущего раунда.

PostgreSQL дополнительно гарантирует:

- один активный раунд на комнату;
- один играющий элемент на раунд;
- один голос пользователя за элемент очереди;
- значение голоса только `+1` или `-1`;
- невозможность добавить в очередь трек из другой комнаты;
- невозможность завершить один элемент и версию очереди дважды.

## Транзакционный сервис

Функции в `backend/app/services/playlist.py` используются будущими REST- или
WebSocket-обработчиками:

- `create_playlist_round` — идемпотентная недельная или ручная ротация;
- `cast_vote` — создание, изменение и toggle-отмена голоса;
- `get_ranked_queue` — сортировка по fair-score;
- `complete_current_and_play_next` — атомарное завершение и выбор следующего трека.

Fair-score считается динамически:

```text
(upvotes - downvotes) - 2 × сыгранные сегодня треки автора
```

Операции изменения очереди блокируют строку комнаты через `SELECT FOR UPDATE`.
Это задаёт единый порядок блокировок и защищает от гонок параллельных запросов.

## Миграции

Применить миграции:

```powershell
cd backend
alembic upgrade head
```

Создать новую после изменения моделей:

```powershell
alembic revision --autogenerate -m "describe change"
```

Проверить SQL без применения:

```powershell
alembic upgrade head --sql
```

Уже опубликованные миграции не редактируются: каждое следующее изменение схемы
добавляется новой ревизией.

## Тесты БД

Тесты используют временную базу в памяти и не затрагивают PostgreSQL разработчика:

```powershell
$env:PYTHONPATH="backend"
python -m unittest discover -s backend\tests -v
```

Проверяются ротация, toggle-голоса, история событий, fair-score, переход плеера,
запрет двух играющих треков и защита от попадания трека в чужую комнату.

## Работа с Git

- разработка задачи ведётся в `feat/*`;
- готовые задачи проходят проверку и попадают в `develop`;
- `main` содержит только версию, готовую к демонстрации;
- `.env`, локальные базы, виртуальные окружения и пользовательские аудиофайлы не
  коммитятся.
